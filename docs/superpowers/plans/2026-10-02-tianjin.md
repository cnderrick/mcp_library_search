# 天津适配器（三源合并）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `tianjin` 城市适配器，把 TJL01 主馆、TJC01 少儿馆两个 ALEPH 目录与中新友好图书馆（Interlib 家族）三源检索结果按 ISBN 归并成统一城市视图。

**Architecture:** `adapters/tianjin.py` 照 shenzhen.py 模式独立实现：模块内 ALEPH client（cookie 会话 + 限速）查两源，第三源直接调用现有 `interlib/` 家族原语（新增 `curlibcode` quirk）；合并为纯函数，book_id 用 `+` 拼接的复合形态自包含多源成员。对外契约与 `_client` 形态不变。

**Tech Stack:** Python 3.12+ / urllib（无新依赖）/ pytest / 既有 fixture 目录结构。

**Spec:** `docs/superpowers/specs/2026-10-02-tianjin-chongqing-adapters-design.md`

## Global Constraints

- 单测不打真网：一切网络走模块内可 monkeypatch 的函数；契约测试 mock `_client` 整体。
- 中文注释与提交信息用全角标点；提交信息不加 Co-Authored-By。
- **不自动提交**：每任务完成后运行全量测试并向用户报告验证方式与改动清单，用户确认后才提交（提交信息已附在任务里）。
- 真网抓取只许只读 GET/POST 检索，限速 ≥4 秒/请求；遇验证码页立即停手并记录。
- 侦察未确认的 HTML 结构以实抓 fixture 为准：本计划的解析器代码按 2026-10-02 已观测结构编写，任务内要求先跑测试与 fixture 对撞，选择器有出入时按 fixture 最小修正并在 NOTES 记一笔。

## Review Focus

1. 归并条目用复合 book_id（如 `TJL01:001303652+TJC01:000448931`）而非 spec 字面的「主馆记录 id」——消除跨调用缓存，get_holdings 无需按 ISBN 重搜（已在 spec 批准后定稿，向用户明示过的偏离）。
2. 同一 ISBN 多版本书（重印）会被合并——按 spec 口径接受。
3. 三源各自独立失败：search ≥1 源成功即返回，全败才报错；holdings 主源失败报错、附属源失败跳过。
4. ALEPH set_number 绑定会话，翻页必须与首搜同会话（client 持 cookie jar）。
5. 验证码页必须抛含馆名的 RuntimeError，不得重试硬闯。
